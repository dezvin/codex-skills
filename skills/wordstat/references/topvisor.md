# Отдельный добор частотностей

Topvisor измеряет выбранный сохранённый набор через Yandex Wordstat. Он не участвует скрытно в семантическом сборе. Запускай его по явной просьбе измерить/добрать частотности либо как видимый согласованный шаг сравнения спроса.

## Контекст и бюджет

Потребуются snapshot ID, регион Topvisor, вид частотности и денежный потолок. Ключи и User ID берутся из окружения, не из входных JSON.

Регион по умолчанию — Россия. Найди provider-specific ключ в справочнике, не предполагай равенство идентификаторов разных сервисов:

```text
python P topvisor regions --search "Россия" --country-code RU --only-countries
```

Это чтение справочника, не платный submit. Проверь возвращённое название/контекст и используй его ключ. Для другого региона сохрани соответствующий найденный key. `searcher_key=0` означает Яндекс. Виды: `1` broad; `2` кавычки; `3` кавычки и фиксированные формы; `5` заданный порядок; `6` порядок и фиксированные формы. Обычный добор использует `1`, если другой тип не поручен.

Цена — рубли. До submit получи свежую оценку. Если бюджет уже выдан и цена укладывается в него, не спрашивай подтверждение каждой небольшой задачи. Если потолка нет, покажи оценку и запроси разрешённую сумму. Если цена выше потолка, не отправляй. Общая сумма потолков частей не должна превышать разрешённый бюджет всей операции.

## Выполнение

`P`, `S` и snapshot — значения текущей работы. Код сам исключает уже известные пары phrase × region × frequency type, включая нулевые и подходящие Wordstat counts; незавершённые задания не покупает повторно. Не составляй вручную список «неизвестных» вместо этого отбора.

```text
python P topvisor create --store S --snapshot-id SNAPSHOT --qualifier REGION_KEY:0:1 --max-cost RUB_CEILING
```

Команда ещё ничего не покупает. Она возвращает `job_id` либо несколько `jobs`. `nothing_to_measure` означает, что добор не нужен; `waiting_existing_measurements` — нужные пары уже в незавершённом задании. Продолжи существующее задание.

```text
python P topvisor estimate --store S --job-id J
python P topvisor submit --store S --job-id J
python P topvisor poll --store S --job-id J
python P topvisor fetch --store S --job-id J
```

При разрешённом потолке можно использовать `topvisor run --store S --job-id J` вместо отдельных шагов; незавершённый remote job продолжай по сохранённому ID. Перед платной отправкой код повторно проверяет, что нужные пары ещё неизвестны и не отправлены другим заданием. При `measurement selection changed` подготовь новый план только оставшегося неизвестного или продолжи уже отправленное задание. Poll делай с разумным интервалом, не горячим циклом. Remote task нужно выгрузить до удаления через 24 часа; локальные результаты после fetch сохраняются.

Если заданий несколько, соблюдай выделенные кодом потолки частей; не заменяй их полным общим ceiling для каждого job. `--max-phrases-per-job` — явное разбиение при практической необходимости, а не выдуманный лимит API.

При `ambiguous_submit` проверь сохранённые данные и подтверждённый remote ID. Если ID неизвестен, останови восстановление: `poll` не выбирает задачу из общего списка аккаунта и сохраняет неопределённость. Не отправляй повторно только потому, что ID неизвестен: возможна повторная оплата. `reopen-ambiguous --allow-duplicate-cost-risk` разрешён лишь после явного принятия этого конкретного риска; смена VPN/сетевого маршрута не делает повтор безопасным.

## Обновление отчёта

Topvisor добавляет отдельные measurement observations и не меняет исходные наблюдения. После fetch повтори экспорт того же снимка: сохранённые внешние замеры будут включены в выгрузку. Покажи известные/неизвестные значения и расхождения. Новый парный benchmark не нужен для каждой работы.

Если Topvisor не настроен или оплата не разрешена, семантический сбор и сохранённое сравнение продолжают работать. Выдай результат с явно неизвестными частотностями.
