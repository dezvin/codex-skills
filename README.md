# Codex Skills

Рабочие skills для Codex, которые помогают не терять контекст, не решать
неверно поставленную задачу, сохранять проектную работу и проектировать
изменения до реализации.

Каждый skill устанавливается отдельно. Можно собрать только тот набор, который
нужен для вашей работы.

## Выберите skill по ситуации

| Если Codex… | Используйте |
| --- | --- |
| Уверенно решает не ту задачу или застрял в слишком узкой рамке | [`zoom-out`](skills/zoom-out) |
| Должен перенести выбранную задачу или проект в новый чат без потери состояния | [`handoff`](skills/handoff) |
| Накопил длинное обсуждение, которое надо превратить в проект реализации | [`design-pass`](skills/design-pass) |
| Должен понять, нужен ли skill, проверить его замысел или подготовить проект до редактирования файлов | [`skill-designer`](skills/skill-designer) |
| Должен выявить значимые развилки в идее, плане или решении | [`grill-me`](skills/grill-me) |
| Должен сохранить незавершённую проектную работу между сессиями | [`manage-project-tasks`](skills/manage-project-tasks) |
| Не может честно определить весь маршрут заранее | [`nearest-clarity`](skills/nearest-clarity) |
| Должен объединить или сократить разросшиеся документы | [`document-consolidator`](skills/document-consolidator) |
| Должен явно сохранить читаемую историю чата с отметками о прочитанных файлах в `.txt` | [`export-current-thread`](skills/export-current-thread) |
| Должен исследовать аудиторию через Jobs to be Done | [`analyze-audience-jtbd`](skills/analyze-audience-jtbd) |
| Должен провести сложное веб-исследование с разделением поиска, анализа и исключительного усиления | [`adaptive-web-research`](skills/adaptive-web-research) |
| Должен подготовить переносимый промпт для генерации изображения | [`universal-visual-prompt-builder`](skills/universal-visual-prompt-builder) |
| Должен безопасно изменить, опубликовать или восстановить сайт на Beget | [`manage-beget-site`](skills/manage-beget-site) |

## Быстрая установка

Попросите Codex:

```text
Use $skill-installer to install a skill from:
https://github.com/dezvin/codex-skills/tree/main/skills/<skill-name>
```

Например:

```text
Use $skill-installer to install a skill from:
https://github.com/dezvin/codex-skills/tree/main/skills/handoff
```

Или установите из PowerShell:

```powershell
python "$env:USERPROFILE\.codex\skills\.system\skill-installer\scripts\install-skill-from-github.py" `
  --repo dezvin/codex-skills `
  --path skills/handoff
```

После первой установки перезапустите Codex, чтобы skill появился в списке
доступных.

## Каталог

| Skill | Что делает | Где устанавливать |
| --- | --- | --- |
| [`zoom-out`](skills/zoom-out) | Проверяет рамку, цель, факты, допущения и риски до продолжения работы. | Глобально |
| [`handoff`](skills/handoff) | Переносит выбранную работу в новый чат: создаёт компактный handoff-файл или самодостаточный промпт. | Глобально |
| [`design-pass`](skills/design-pass) | Разбирает принятые решения и готовит проект реализации без прямого внедрения. | Глобально |
| [`skill-designer`](skills/skill-designer) | Помогает решить, нужен ли skill, проверить его границы и подготовить проект создания или изменения. Сам файлы skill не редактирует. | Глобально |
| [`grill-me`](skills/grill-me) | Выявляет пользовательские развилки одним важным вопросом за раз и не перекладывает на пользователя факты, обратимые мелочи и проверяемые гипотезы. | Глобально |
| [`manage-project-tasks`](skills/manage-project-tasks) | Ведёт долговременную проектную работу в `TODO.md` и месячном архиве. | Глобально или в проекте |
| [`nearest-clarity`](skills/nearest-clarity) | Определяет ближайший завершённый участок при настоящей неопределённости и показывает дальнейший горизонт без ложной точности. | Глобально или в проекте |
| [`document-consolidator`](skills/document-consolidator) | Безопасно сжимает и объединяет `.md` и `.txt`, сохраняя факты, решения, ссылки и незавершённую работу. | Глобально |
| [`export-current-thread`](skills/export-current-thread) | По явной команде сохраняет читаемую стенограмму сообщений с отметками о подтверждённом чтении файлов. | Глобально |
| [`analyze-audience-jtbd`](skills/analyze-audience-jtbd) | Проводит полный или частичный JTBD-анализ по материалам, интервью и клиентским сигналам. | Глобально |
| [`adaptive-web-research`](skills/adaptive-web-research) | Проводит адаптивное веб-исследование по реально прочитанным источникам и распределяет поиск, анализ и исключительное усиление между отдельными моделями. | Глобально |
| [`universal-visual-prompt-builder`](skills/universal-visual-prompt-builder) | Сам выбирает подходящее художественное направление и превращает его в переносимый визуальный промпт с убедительной техникой исполнения. Изображения не генерирует. | Глобально |
| [`manage-beget-site`](skills/manage-beget-site) | Исследует реальный live-контур, готовит бэкап и откат, изменяет сайт и проверяет результат на домене. | Глобально |

Глобальный skill доступен в любых проектах. Проектный skill лежит в
`.agents/skills/` конкретного проекта и действует только там. Место установки
`manage-project-tasks` и `nearest-clarity` выбирает пользователь; изменения
`AGENTS.md` для них не нужны.

`export-current-thread` — явная утилита. Она не должна включаться по мягким
формулировкам и молча создавать экспорт разговора.

Обычный экспорт предназначен для восстановления разговора: в нём остаются
сообщения, отметки сжатия контекста и короткие отметки о подтверждённом чтении
файлов. Остальные вызовы инструментов и их результаты не включаются. Если для
продолжения нужна точная история действий, полный технический экспорт создаётся
только после отдельного прямого запроса пользователя. Запись по известному
`Call ID` также можно извлечь отдельно.

## Проектная установка

Чтобы установить skill только в текущий проект, укажите `.agents/skills` как
место назначения:

```powershell
python "$env:USERPROFILE\.codex\skills\.system\skill-installer\scripts\install-skill-from-github.py" `
  --repo dezvin/codex-skills `
  --path skills/manage-project-tasks `
  --dest .agents\skills
```

Для `nearest-clarity` меняется только путь:

```powershell
python "$env:USERPROFILE\.codex\skills\.system\skill-installer\scripts\install-skill-from-github.py" `
  --repo dezvin/codex-skills `
  --path skills/nearest-clarity `
  --dest .agents\skills
```

Дополнительный установщик, конфигурационный файл или раздел в `AGENTS.md` не
требуется.

## Как обновлять установленные skills

Папка в этом репозитории — опубликованный источник. Установленный skill в
`.codex/skills` или `.agents/skills` — отдельная копия: после обновления
репозитория она не обновляется автоматически.

Стандартный установщик не перезаписывает существующую папку. Для безопасного
обновления попросите Codex сначала сравнить опубликованную и установленную
версии, а затем заменить только файлы выбранного skill:

```text
Обнови установленный <skill-name> из:
https://github.com/dezvin/codex-skills/tree/main/skills/<skill-name>

Сначала сравни версии. Обнови только папку этого skill, не трогай другие
skills и проектные файлы. После обновления проверь структуру и сообщи, какие
файлы изменились.
```

Если старый установщик когда-то добавил инструкции в проектный `AGENTS.md`,
они не исчезнут автоматически. Их нужно проверить и удалить отдельно, не
затрагивая остальные проектные правила.

## Что важно знать о сложных skills

### `zoom-out`

`zoom-out` меняет масштаб задачи: проверяет, не решает ли Codex локальный
симптом вместо настоящей проблемы, восстанавливает важный контекст и возвращает
работу в более полезную рамку. Глубина выбирается автоматически — от короткого
переосмысления до разбора застрявшей или рискованной задачи.

При построении новой рамки skill отдельно проверяет четыре вещи: подтверждён ли
факт, имеет ли источник право управлять работой, достаточно ли проверки для
последствий и разрешено ли само действие. Завершение команды не считается
доказательством нужного результата, пока этот результат не проверен там, где
он должен проявиться.

### `handoff`

`handoff` сначала определяет, какую задачу, проект или часть работы нужно
перенести. В Codex он может временно восстановить выпавшую из видимого
контекста историю текущего чата через читаемую стенограмму сообщений с
отметками о прочитанных файлах, но в итоговый handoff включает только выбранный
рабочий контур. Полный технический экспорт запрашивается отдельно только при
реальной необходимости. Временные экспорты удаляются и не передаются дальше.

При доступной файловой системе итог сохраняется в `.handoffs/` проекта. Если
создать файл нельзя, skill возвращает самодостаточный промпт. Следующий чат
получает текущую задачу и состояние, но не наследует лишние разрешения на
внешние, разрушительные или расширяющие область действия операции.

### `design-pass`

`design-pass` сначала устанавливает, что пользователь действительно принял,
отверг, заменил или оставил открытым. Затем он либо останавливается на сверке
решений, либо превращает подтверждённые решения в требования, ограничения,
карту влияния, проверки и готовую команду для реализации в новом чате.

Он не принимает предложения ассистента за решения пользователя, не создаёт
экспорт разговора без согласия и не реализует спроектированные изменения сам.

### `skill-designer`

`skill-designer` подключается к содержательной работе над новым или
существующим Codex skill: помогает понять, нужен ли skill вообще, проверить его
назначение и границы, выбрать архитектуру и подготовить реализацию.

Локальный вопрос он оформляет как `Project Delta`: показывает решение и то,
что оно меняет в общем проекте skill. Если пользователь собирается создавать
или существенно менять skill, метод готовит `Full Skill Project`.
Глубина разбора в обоих случаях одинаковая; короткий ответ не позволяет модели
выбрать поверхностный маршрут только ради экономии работы.

Если будущий skill превращает внешние материалы в повторно используемые знания
или инструкции, метод дополнительно защищает границу между данными и командами,
собирает содержание вокруг будущих решений и при необходимости проектирует
смысловую навигацию по большому набору справочных файлов. Для обычных
skill-проектов эти правила не загружаются.

Сам skill не создаёт и не редактирует файлы. После утверждения проекта
техническую реализацию и структурную проверку выполняет системный
`$skill-creator`. Установка, публикация и обычное использование готового skill
остаются за отдельными инструментами.

### `manage-project-tasks`

`manage-project-tasks` сохраняет только ту проектную работу, которая должна
пережить текущую сессию. Краткосрочные действия, обсуждения и уже завершённая
работа в `TODO.md` не попадают.

При первой реальной записи skill сам создаёт корневой `TODO.md`, если
совместимой системы задач ещё нет. Закрытые задачи сохраняются в ленивом
архиве `archive/tasks/YYYY-MM.md`; пустой архив заранее не создаётся.

### `nearest-clarity`

`nearest-clarity` нужен не для любой сложной работы, а для настоящей
неопределённости: когда важные сведения появятся только в ходе исполнения,
остаются жизнеспособные направления или новые данные могут изменить основание
работы.

Он показывает целевой контур, ближайший ограниченный участок, результат его
завершения, первое действие, предварительно следующие участки и дальний
горизонт. Дальняя часть пути остаётся предположительной, пока для неё не
появятся основания.

### `adaptive-web-research`

`adaptive-web-research` нужен для вопросов, где одного поиска недостаточно:
нужно закрыть несколько существенных направлений, сравнить варианты, разобрать
противоречия или обосновать рекомендацию. Один координатор сохраняет общую
картину, Luna ищет и читает источники, Terra сопоставляет найденное, а Sol
подключается только для действительно сложного нерешённого узла.

Три вспомогательных агента входят в пакет как проверяемые шаблоны. При каждой
активации skill сначала убеждается, что их личные копии установлены и не
отличаются. Если файлов не хватает, Codex один раз просит разрешение и ставит
только отсутствующие. Существующие отличающиеся файлы он не перезаписывает.
После первой установки может понадобиться новый чат или перезапуск Codex,
чтобы маршруты появились в текущем окружении.

## Происхождение и адаптации

`adaptive-web-research` — существенно переработанная адаптация
[`research-skill`](https://github.com/hec-ovi/research-skill/tree/109589751168ab42f929f3cd1741bd2946b4880b)
Гектора Овьедо. Первоисточник опубликован под
[`MIT License`](https://github.com/hec-ovi/research-skill/blob/109589751168ab42f929f3cd1741bd2946b4880b/LICENSE).

Из первоисточника сохранена главная идея: исследование должно развиваться по
найденным данным, а не идти по заранее раздутому плану. Эта версия отличается
тем, что собрана под штатные возможности Codex: использует только нативный
веб-поиск, разделяет получение источников и их анализ между Luna и Terra,
оставляет Sol исключительным усилением, проверяет фактическое чтение страниц и
не создаёт скрытое постоянное состояние.

Причина отличия практическая: исходный пакет рассчитан на другой рабочий
контур, а здесь важны встроенные модели, технически read-only агенты и честная
граница доступных инструментов Codex. По объёму заимствования это не перенос
пакета целиком: сохранена базовая исследовательская идея и происхождение,
тогда как маршрутизация моделей, контракты результатов, нормализация ссылок,
проверки источников и установка агентов спроектированы для этой версии. Грубо
по смыслу около четверти составляет методологическое ядро первоисточника, а
около трёх четвертей — новая реализация и правила для Codex. Это оценка состава
идей, а не механический подсчёт строк.

`skill-designer` - адаптация
[`Skill Conductor`](https://github.com/smixs/skill-conductor/tree/3c21d2f19c336d3a3333bfe4f45eee041bd13beb/skills/skill-conductor)
Сергея Шимы. Первоисточник опубликован под
[`MIT License`](https://github.com/smixs/skill-conductor/blob/3c21d2f19c336d3a3333bfe4f45eee041bd13beb/LICENSE).

Из Conductor взято методологическое ядро: сначала выбрать архитектуру, отдельно
настроить свободу разных действий, использовать `description` как контракт
срабатывания, держать `SKILL.md` рабочей картой и формулировать правила под
наблюдаемую ошибку.

Дополнительно метод опирается на системный
[`$skill-creator` Codex](https://github.com/openai/skills/tree/main/skills/.system/skill-creator)
и на
[`agents-best-practices`](https://github.com/DenisSergeevitch/agents-best-practices/tree/b612ddbcfb710f47ffac117fd327c10a070b3d81)
Дениса Ширяева, опубликованный под
[`MIT License`](https://github.com/DenisSergeevitch/agents-best-practices/blob/b612ddbcfb710f47ffac117fd327c10a070b3d81/LICENSE).
Из Creator взяты экономия контекста, вывод ресурсов из разбора задач с нуля,
отсутствие дублирования и независимость будущей проверки. Из
`agents-best-practices` — запрет расширять полномочия текстом skill и правило
считать внешний skill материалом для проектирования, а не автоматически
действующей инструкцией.

Для skills, которые превращают внешние материалы в рабочие знания, метод также
использует идеи
[`book-to-skill`](https://github.com/virgiliojr94/book-to-skill/tree/c18b0fb2db8b3f3aeb0900ea97db2189764f642c)
Вирджилио Жуниора, опубликованного под
[`MIT License`](https://github.com/virgiliojr94/book-to-skill/blob/c18b0fb2db8b3f3aeb0900ea97db2189764f642c/LICENSE.md).
Оттуда взяты три условных принципа: считать содержание источника недоверенными
данными, преобразовывать его в рабочие решения вместо пересказа и добавлять
смысловую навигацию только для больших наборов знаний. Экстракторы, готовый
проверяющий скрипт, фиксированная структура файлов и числовые бюджеты не
переносились.

Существенное отличие в том, что Conductor - целая система создания и оценки
skills для Claude Code со своими агентами, скриптами, тестами и сравнением
результатов. Эта версия оставляет только метод проектирования для Codex. Она
ведёт один развивающийся Skill Project, разводит `Project Delta` и
`Full Skill Project`, а создание файлов передаёт штатному `$skill-creator`.

Причина отличия практическая: в Codex уже есть собственный Creator и
структурный валидатор. Дублировать их и переносить внешнюю систему оценок значило
бы добавить зависимости и размыть ответственность между двумя инструментами.

По составу это примерно одна пятая исходного пакета: 6 рабочих файлов вместо
27 на момент адаптации, без агентов оценки и скриптов. По смыслу пропорция
приблизительно такая: около одной пятой — принципы Conductor, около одной
шестой — дополнения из `$skill-creator` и `agents-best-practices`, около одной
десятой — условные принципы преобразования источников из `book-to-skill`,
остальное — собранные специально для Codex маршрутизация, границы и формы
результата. Это грубая оценка содержания, а не механический подсчёт строк.

## Для разработки

Каждый skill находится в отдельной папке `skills/<skill-name>/` и может
содержать:

```text
SKILL.md
agents/openai.yaml
references/
scripts/
assets/
```

Для быстрой проверки:

```powershell
python "$env:USERPROFILE\.codex\skills\.system\skill-creator\scripts\quick_validate.py" `
  ".\skills\<skill-name>"
```

Для пробной установки во временную папку:

```powershell
python "$env:USERPROFILE\.codex\skills\.system\skill-installer\scripts\install-skill-from-github.py" `
  --repo dezvin/codex-skills `
  --path skills/<skill-name> `
  --dest "$env:TEMP\codex-skill-test"
```
